# ADR-0002：板级层移植

- 状态：已采纳
- 日期：2026-08-29

## 1. 背景与目标

芯片层就位后，NuttX 还需要"板"的概念才能启动：板级初始化流程（boot → late_initialize → bringup）、外设引脚与资源定义（board.h）、链接脚本（内存布局）、以及一套可运行的板级配置。目标板为乐鑫 ESP32-P4-Function-EV-Board。

## 2. 适配流程

1. **公共板级目录**（`boards/risc-v/esp32p4/common/`）
   - `src/`：各外设的板级注册辅助（I2C/SPI/ADC 等按 Kconfig 条件编译，含显示注册辅助）；
   - `scripts/`：ESP32-P4 全套链接脚本——`esp32p4_aliases.ld`（ROM 符号别名）、`esp32p4_flat_memory.ld`（MEMORY 区域定义：flash 映射区、HP SRAM、TCM、LP SRAM）、`esp32p4_sections.ld` / `esp32p4_sections.rev3.ld`（段布局，rev3 对应芯片版本 ≥3.0 的布局差异）；
   - `Kconfig` / `CMakeLists.txt` / `Makefile`：公共板级构建接线。

2. **目标板目录**（`boards/risc-v/esp32p4/esp32p4-function-ev-board/`）
   - `include/board.h`：引脚、时钟、外设资源宏定义；
   - `src/esp32p4_boot.c`：`esp_board_initialize()`（早期板级初始化）与 `board_late_initialize()` → `esp_bringup()`；
   - `src/esp32p4_bringup.c`：按 Kconfig 逐个注册外设（I2C、GPIO、以太网、**MIPI-DSI 初始化、/dev/fb0 注册**等）；
   - `src/esp32p4_appinit.c`：`board_app_initialize()`（NSH `BOARDIOC_INIT` 入口）；
   - `src/esp32p4_reset.c`：`boardctl(BOARDIOC_RESET)` 支持；
   - `src/esp32p4_fb0_stub.c`：在 DSI 驱动之上注册 `/dev/fb0`（帧格式 1024×600 RGB565、双缓冲 pan 显示）；
   - `configs/`：一套测试配置（nsh、usbconsole 等），本项目的正式配置在 vendor 层维护（见 ADR-0004）。

3. **注册挂接**
   - `boards/Kconfig`：新增 `ARCH_BOARD_ESP32P4_FUNCTION_EV_BOARD` 选择项、`ARCH_BOARD` 默认值、板级与公共 Kconfig 的 `source` 条目。

## 3. 关键决策

- **只移植一块目标板**：不带入同芯片的其他板卡，缩小维护面；
- **初始化路径采用内核 late-init**：`CONFIG_BOARD_LATE_INITIALIZE=y` → `board_late_initialize()` → `esp_bringup()`。原因：树内板级的 `board_app_initialize()` 是空实现，NSH 的 `BOARDIOC_INIT` 路径不承载外设初始化；内核 late-init 是 openvela 板级的正统初始化入口（这一选择来自真机排查，见 docs/issues/ISSUE-002）；
- **显示设备注册放在板级**：芯片层 DSI 驱动只暴露帧缓冲 API（获取缓冲、翻转、刷新），`/dev/fb0` 字符设备由板级 `esp32p4_fb0_stub.c` 注册，保持芯片层与 NuttX 设备模型的解耦。

## 4. 验证方式

- 板级选择可用：`CONFIG_ARCH_BOARD_CUSTOM_DIR="boards/risc-v/esp32p4/esp32p4-function-ev-board"` 后配置/编译通过；
- 链接脚本生效：ELF 程序头显示 `.flash.text` 位于 0x40000000、`.iram0.text`/`.dram0` 位于 0x4ff40000、入口点在 IRAM；
- 真机：内核 late-init 执行，bringup 中的初始化日志出现在 ramlog（dmesg）。
